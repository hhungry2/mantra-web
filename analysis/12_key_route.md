# 鍵とロックドアのルート対比表

## 結論

「3つ目の鍵」を、開始地点からの推奨ルートで数える場合は、次の場所です。

**画面231（ワールド座標 7,14）の地下洞窟、タイル座標(7,6)**

- 敵/配置: `sprite=2144`, `movementType=1`, `attributes=34`
- `attributes=34` は `canBeHeld(2) + insubstantial(32)`
- `deadItem/drop=150` = Key
- 画面231には、もう1体の拾得物(`sprite=2144`, (8,6), drop=61)もある
- この場所は画面217（9,13）の北進路に対して南西側にあり、TextData #11「The monster in the Southwest caves stole the key to the North Pass.」と整合する（画面32＝ワールド(0,2)のNPCが`message=11`で提示。`main.js:229`が`textMsgs[message-1]`を引くため`message`は1始まり、配列indexでは10）
- この拾得物は宝箱。`message=5` → `textMsgs[4]`「You have found an item: 」＋アイテム名（`main.js:229-234`, `Dialogs.c:186`）

ただし、元ソースには鍵の通し番号や固有の鍵IDはない。すべての鍵が同じアイテム番号150で、どの鍵でもどの`doorEnemy`を開けられる。そのため、以下の順序はデータの配置・到達性・看板文から推定した推奨ルートであり、唯一固定の正解順ではない。

## 推奨ルート対応

鍵とドアは固有ペアではないが、進行例としては次の対応が分かりやすい。

| 進行 | 取得する鍵 | 使用するドア | 使用後の遷移 |
|---:|---|---|---|
| 1 | 画面236のRhino Boss | 画面0のドア | 画面61へ |
| 2 | 画面191のBlob Boss | 画面191のドア | 画面175へ |
| 3 | **画面231の拾得物** | **画面217のNorth Passドア** | **画面89へ** |
| 4 | 画面217のCrab Boss | 画面236のドア | 画面235へ（→画面251の宝箱） |

この順序では、3つ目の鍵は「画面231」、3つ目に開ける重要ドアは「画面217のNorth Pass」です。画面169の鍵は後半取得分で、プレイヤーの移動順によって取得順は変わります。

なお画面236のドアは近道ではなく、**画面251の宝箱への唯一の入口**です（下記「1本目の分岐」参照）。
1本目のRhino鍵をここに使う分岐Aも成立し、その場合は表の順序が入れ替わります。

## 到達可能性の検証（map.jsの移動規則でBFS）

開始地点は `config.js` の `START_SCREEN = 124`（ワールド(12,7)）、`START_TILE = (8,5)`。
`mods & STANDABLE(1)` を歩行可、画面端は `getNeighbor` で隣接画面へ、`isDoor(2)` タイルは
`special`/±128 で遷移、`ai=15`のロック敵タイルは鍵使用まで通行不可、として全探索した結果:

- **鍵0本の状態で到達できる鍵は画面236のRhino Bossのみ**（44画面が到達可能）。
  画面191・217・231・251・169はいずれも鍵0本では到達できない。
- 画面236への経路は鍵不要:
  124 → 108/109/110 → 94/93 → 77/76/75 → 91 → **107**（タイル(5,3)の
  `leadsToUnderWorld`ドア、ロックなし）→ 235 → 219 → 203/204 → 220/221 → 237 → 236。
- 1本目の鍵の使い道は**2通りあり、どちらでも詰まない**（下の「1本目の分岐」参照）。
- **最大のゲートは画面0のドア**。ここを開けると到達画面が44→188に増え、
  画面191・217・231・169の鍵が一度に取得可能になる。
- **画面236のドアは画面251の宝箱への唯一の入口**。画面235は右下（行7-9、列7-14）が
  同一画面内で分断された袋小路になっており、そこへは画面236のドア(1,4)→235(14,4)で
  降りるしかない。この袋小路の行9列7-14から画面251の行0へ抜けて宝箱に到達する。
  （画面単位で数えると画面251は左端列だけ別途到達できるため「+0画面」に見えるが、
  タイル単位で見ると宝箱タイル(7,5)はこのドア無しでは到達不能）
- 画面191・217のドアは進行ゲートではなく近道:
  - 画面191のドア → 新規到達は画面175のみ（+1）
  - 画面217のドア（North Pass）→ 新規到達は画面243のみ（+1）。行き先の画面89は
    画面0のドアを開けた時点で既に徒歩到達可能

鍵の入手タイル単位での到達判定:

| 開けたドア | 到達タイル数 | 取得可能な鍵の画面 |
|---|---:|---|
| なし | 2,827 | 236 |
| 画面0 | 12,399 | 169, 191, 217, 231, 236 |
| 画面0 + 画面236 | 12,478 | 169, 191, 217, 231, 236, **251** |
| 画面0 + 画面191 | 12,475 | 169, 191, 217, 231, 236 |
| 画面0 + 画面217 | 12,430 | 169, 191, 217, 231, 236 |
| 画面236のみ（画面0を開けず） | — | 236, **251** |

## 1本目の分岐

1本目（画面236のRhino Boss）の使い道は2通りあり、BFSでどちらも成立を確認済み。

| 分岐 | 使うドア | 直後に得られるもの | 使用後の所持鍵 |
|---|---|---|---:|
| **A** | 画面236のドア | 画面251の宝箱＝鍵2本目 | 1本 |
| B | 画面0のドア | 画面191・217・231・169の鍵4本が解禁 | 0本 |

分岐Aの経路（画面0のドアを一切開けない条件で検証、`(251,7,5)`到達可 = True）:

```
124 → 108 → 109 → 110 → 94 → 93 → 77 → 76 → 75 → 91
  → 107 [(5,3) leadsToUnderWorld・ロック無し] → 235 → 219 → 203 → 204
  → 220 → 221 → 237 → 238 → 254 → 253 → 252 → 237 → 236   ★Rhino Boss = 鍵1本目
  → 236のドア(1,4)を開錠 → 235(14,4) に着地【袋小路区画】
  → (14,5) → (14,6) → 行7列10-14 → 行8列9-14 → 行9列7-14
  → 251 の行0へ → 宝箱(7,5)   ★鍵2本目
```

- 235側の(14,4)のドアは`special`で236(1,4)へ戻る双方向ドアで、**235側にはロック敵が0体**。
  宝箱地点から再探索すると45画面に戻れ、画面0のドアタイルにも到達できるため**詰みにならない**。
- 分岐Aのほうが鍵を1本増やしてから画面0へ向かえるので、進行としては素直。

したがってデータ上確定しているのは次の3点:

1. 1本目の鍵は画面236のRhino Boss（他の5本は鍵0本では到達不能）
2. 画面251の宝箱を取るには画面236のドアを開ける必要がある（唯一の入口）
3. 画面191・217・231・169の鍵を取るには画面0のドアを開ける必要がある

これ以外の順序（画面191・217・231・169をどの順で回るか、画面191・217のドアをいつ開けるか）は
プレイヤーの移動次第で入れ替わる。上の推奨順はTextData #11のクエスト文
（南西の洞窟の鍵→North Pass）に沿った一例。

## 元Cソース上の根拠

- `GameTypes.h:315`: `doorEnemy = 15`
- `GameTypes.h:147-158`: `isSpecialItem=64`, `hasSpecialRoutine=512`
- `Saric.c:182-192`: アイテム150を`keySpecialItem()`へディスパッチ
- `Saric.c:241-308`: 前方の`doorEnemy`に当たれば`health=0`、効果音134、鍵を1個消費
- `Enemies.c:162-165`: 開いたドアの元スロットを`g_DeathRecord`に記録
- `LoadData.c`/抽出JSON: 画面・敵配置・`deadItem=150`
- TextData #11（`text.json`の配列index 10）: Southwest cavesとNorth Passの関係。
  画面32＝ワールド(0,2)のNPCが`message=11`で提示。`main.js:229`が`textMsgs[message-1]`を
  引くため`message`は1始まり
